# SynthForge Studio P6.5：场景拼装区实施计划（待规划）

> **状态**：未开工。本文档只记录设计约束与待决问题，Task 拆解与测试清单等进入 P6.5 时再补。
>
> **排位**：P6（unity 区）之后、P7（打磨与打包）之前。理由：「导入外部文件夹」那套 UI 与 `dialog.pickFolder` 在 P6 才落地，本区直接沿用，不重复造一套。

**Goal：** 让用户从资产库勾选多个已有资产，自动拼成一个完整场景并导出，全程不需要手动打开 Blender 做 Append。

**Architecture：** 新增独立的 `assembler` 区，复用 AgentOrchestrator 的两阶段主循环；区别在于执行前不再「从空场景建模」，而是用 `bpy.data.libraries.load` 把选中的 blend 逐个 append 进来，再按布局摆放、统一导出。

## 为什么单独一个区

现有两条能力都覆盖不到：

| 能力 | 输入 | 行为 |
|---|---|---|
| 新建（blender 区） | 一句话 | 从空场景建一整个场景 |
| 修改（blender 区） | 一句话 + 一个资产 | 打开那个 blend 改 |

「把 A、B、C 拼起来」既不是新建也不是修改：它要读多个 blend、保留各自层级、决定位置，最后产出一个新资产。

## 交互

1. 左侧栏新增 `assembler` 区，与 `blender` / `unity` 并列；**左上角「导入文件夹」**，复用 P6 的 `dialog.pickFolder` 那套交互
2. 选中后文件树切到该文件夹，勾选参与拼装的资产（可串子目录）
3. 输入一句布局描述 → 草稿卡确认（复用 P4 Task 7 的 ask/draft 流程，`mode:"assemble"`）
4. 计划卡分组 = 摆放批次 → 点开始 → 在工作区内选输出子目录（复用 P4 的 `folderPick`，可现场新建）
5. 导出 `scene_<name>.glb` + `.fbx` + `.blend` 到该目录
6. 完成后对话区给「在文件夹中显示」按钮（`fs.operate reveal`）

## 独立工作区（像 unity 导入工程）

拼装区**不绑定 `ModelLibrary`**，根目录由用户指定：

1. 「导入文件夹」→ `dialog.pickFolder {purpose:"assemblerWorkspace"}`（P6 已有），任意路径、不校验是否在库内
2. 选中后 `CoreApp` 重建一个指向该路径的 `AssetLibrary` 实例，广播 `fileTree.changed {area:"assembler", reason:"full"}`
3. 文件树、多选、`file.read`、`reveal`、`folderPick` 全部在这个根内工作
4. 记忆上次工作区，下次进入直接恢复

与 blender 区的区别：

| | blender 区 | assembler 区 |
|---|---|---|
| 根目录 | 固定 `Documents/SynthForgeStudio/ModelLibrary` | 用户导入，任意路径 |
| 切换 | 无 | 可随时重选；切走时丢弃已选素材 |
| 产物 | 只能写到库内 | 写到工作区内任意子目录 |

实现要点：

- `CoreApp` 增加 `std::unique_ptr<AssetLibrary> m_assemblerLibrary`，与 `m_library` 并列
- `fileTree` / `fs.operate` / `file.read` / `folderPick.submit` 的 handler 按 `area` 路由到对应实例
- `area == "assembler"` 且未导入工作区时返回 `no-workspace`，前端提示先导入

命名问题：工作区是用户自己组织的，同目录内文件名天然唯一；只剩跨子目录同名（`buildings/lamp.blend` 与 `props/lamp.blend`）append 后变成 `lamp` / `lamp.001`，不影响导出，但计划卡引用物体时要按 collection 定位。

## 核心实现

```python
import bpy, os
# link=False 是复制不是引用：拼装结果自包含，删掉源文件也不会坏
with bpy.data.libraries.load(path, link=False) as (src, dst):
    dst.collections = src.collections     # 带 collection 才能保住层级
for coll in dst.collections:
    if coll:
        bpy.context.scene.collection.children.link(coll)
```

## 执行前清场

与 blender 区一致：append 之前先清空当前场景，否则上一次任务的残留会混进拼装结果（同 P4 Task 3 的 `kClearScene`）。

## 待决

- 布局由 LLM 直接给坐标，还是 append 后摊开成一行让用户拖
- 拼装结果能否作为输入再参与下一次拼装（嵌套）——同一工作区内可直接选
- 拼装中途能否增删资产（已摆好位置的能否撤掉）
- 多选上限：几十个资产同时 append 会卡内存，是否限制单次数量
- 切换工作区时，已选素材和对话历史是否保留
